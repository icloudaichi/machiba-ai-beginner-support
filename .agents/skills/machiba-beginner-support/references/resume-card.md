# 再開カード（GitHub未反映時の代替）

標準の再開情報は参加者自身の非公開アプリrepoにあるセッションIssueへ残す。このカードは、自動記録ツールがない、GitHubへ接続できない、またはread-backできないときだけ使うローカルな代替手段。

```markdown
## 再開カード

- 今日の目的：
- PC・OS：
- 使用中のAI：
- 相談履歴の表示名：未確認／本人確認済み表示名
- セッションIssue：未作成／未確認／Issue番号
- GitHub記録：未開始／ローカル保存のみ／read-back済み
- GitHub接続：未確認／準備中／接続済み
- Cloudflare接続：未確認／準備中／接続済み
- Google Drive提出：未準備／ZIP準備中／承認待ち／アップロード中／Drive確認済み／未確認
- GitHub提出記録：未記録／同期待ち／Issue確認済み
- 共有ファイル名への表示名使用：未確認／了承済み
- Drive接続の承認：不要／未確認／了承済み
- Driveアップロードの承認：未確認／了承済み
- 提出ファイル名：未確認／確認済みファイル名
- 提出経路：未確認／ブラウザ／コネクタ／API
- 成果物Drive URL：未確認／read-back済み個別URL
- 案内方法：未確認／ゆっくり伴走／一操作ずつ／要点案内
- 最後に確認できたこと：
- 現在の画面・表示：
- 試したこと：
- 次にする一つ：
- 担当者に確認してほしいこと：
- 秘密情報を含まない確認：済／未確認
```

## 作成時のルール

- 分からない項目は推測せず「未確認」とする。
- エラーは秘密情報を除いて短く要約する。必要な場合だけ全文を別に用意する。
- 会話全文、コマンドの生出力、ローカルパス、ユーザー名、メールアドレス、アカウントIDを書かない。
- 次の操作は一つだけ書く。
- 本人が読める普段の日本語を使う。
- カードを公開repoや外部チャットへ自動送信しない。
- 提出用表示名は、共有フォルダでほかの参加者やリンク所持者にも見えると本人へ説明し、ファイル名への使用を別に確認する。
- Drive URLは実際に一覧またはメタデータから確認できた個別ファイルURLだけを書く。提出先フォルダURLや推測URLを成果物URLとして書かない。
- Driveの共有権限、ほかの参加者のファイル、秘密情報をカードへ書かない。
- GitHub接続が戻ったら、自動記録ツールの`sync`で未反映分を同期する。ツールがなければ同期方法を推測しない。

## 再開時

同じcloneまたは別worktreeでは、最初に自動記録ツールの`status`を使う。別cloneまたはローカル状態消失時は、本人が示したIssue番号を`resume --issue`へ渡す。Issue番号が分からない場合は似たタイトルから推測しない。

セッションIssueをread-backできる場合はIssueを正本として使う。Issueへ未同期のカードがある場合は、同期結果をread-backしてからIssueを正本へ戻す。

カードしか読めない場合も、記録済みの成功段階をやり直さない。GitHub・Cloudflareが「接続済み」で、新しい認証エラーや環境変更の兆候がなければ「次にする一つ」から再開する。記録が古い、またはエラーの兆候がある場合だけ、疑わしい側を一つずつ安全に再確認する。

Drive提出が`Drive確認済み`なら再アップロードしない。GitHub提出記録が`未記録`または`同期待ち`なら、Issue記録だけを再開する。Driveが`アップロード中`または`未確認`なら、まず指定フォルダ直下で完全一致するファイル名と親を一度だけ確認する。同名ファイルを上書きせず、確認できない場合は提出済みと扱わない。
