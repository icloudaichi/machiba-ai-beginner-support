# Google Driveへの成果物提出

## 提出先

2026年8月23日の初回講座では、次の「受講者共有用」フォルダへ提出する。

- 提出先：<https://drive.google.com/drive/folders/1sEgVfferbokBUQU440bChvVYyGk338hs>

リンク所持者が閲覧・追加できる共有領域である。自分の提出ファイルだけを新規追加し、既存ファイルを開く、更新する、移動する、改名する、削除する操作は行わない。共有権限を変更しない。

この直接URLと書き込み権限は公開教材から見える。2026年8月23日18:00の講座終了後、運営は新規追加を止めるため、この提出先の共有権限を見直す。AIは権限変更を自動実行しない。

## 標準経路

標準はブラウザからの手動アップロード。Google DriveコネクタまたはAPIがすでに利用可能なら、本人が希望すればAIによるアップロードを選べる。

未接続でも、本人が「AIからDriveへ提出できるよう接続してみたい」と希望し、講座時間とPC環境に余裕がある場合だけ、発展課題として接続を案内できる。初回講座の必須課題にはしない。

AIによる経路でも、対象フォルダIDを固定した**新規アップロードだけ**を許可する。既存ファイルの更新・削除・移動・共有設定変更をしない。

接続を始める場合は、使用中のAIとOSを確認し、Google公式OAuthまたは公式コネクタだけを使う。画面名やボタン名は変わり得るため、現在表示されている画面を一つずつ確認する。権限画面ごとに目的、見える情報、変わることを説明し、本人の確認後に進む。APIキー、認証コード、トークンをチャットへ貼らせない。

コネクタ接続の承認は、ファイルをアップロードする承認ではない。接続後も、書き込み直前に対象ファイル、提出先、影響を示して別の確認を得る。同じ箇所で3回、または約7分止まったら接続を中断し、標準のブラウザ提出へ戻る。

## ファイルを作る前の確認

1. 成果物の表示名を一問だけ確認する。本名は不要で、ニックネームでよい。
2. 「この表示名は共有フォルダ内で、ほかの参加者やリンク所持者にも見える」と説明する。
3. private GitHub Issueへの表示名保存とは別に、ファイル名へ使ってよいか本人へ確認する。
4. 次の形式でZIP名を決める。

```text
YYYY-MM-DD_表示名_成果物.zip
```

例：`2026-08-23_だいち_成果物.zip`

表示名には `/`、`\\`、`:` など、ファイル名として扱いにくい文字を使わない。

ZIPを作る前と作った後に、次が含まれていないことを確認する。

- `.env`、`.env.local`などの環境変数ファイル
- トークン、秘密鍵、認証コード、パスワード
- `node_modules/`
- `.wrangler/`
- `.git/`のローカル状態
- 本物の参加者・顧客・連絡先・請求情報
- 個人用のスクリーンショットや会話全文

除外を確認できないZIPはアップロードしない。

## アップロード前の承認

Google Driveへのアップロードは、標準開始プロンプトのGitHub記録承認には含まれない。書き込みの直前に、次の3点を本人へ示して一問で確認する。

```text
アップロードするファイル：2026-08-23_表示名_成果物.zip
追加先：2026.8.23開催／受講者共有用
影響：リンク所持者からファイル名と内容を見られる共有領域へ、新しいファイルを1件追加します。共有権限や既存ファイルは変更しません。

この内容でアップロードしてよいですか？
```

明確な了承前にファイルを追加しない。

## ブラウザで提出する

一度に一操作だけ案内する。

1. [受講者共有用フォルダ](https://drive.google.com/drive/folders/1sEgVfferbokBUQU440bChvVYyGk338hs)を開く。
2. Googleアカウントで開けたことを確認する。
3. 対象ファイル、対象フォルダ、影響を説明し、本人の承認を得る。
4. 「新規」から「ファイルのアップロード」を選び、確認済みZIPを1件だけ選ぶ。
5. アップロード完了表示を待つ。
6. フォルダ一覧に同じファイル名が表示されたことを確認する。
7. そのファイルの親が指定フォルダID `1sEgVfferbokBUQU440bChvVYyGk338hs`であることを、一覧またはメタデータから確認する。
8. 取得できる場合だけ個別ファイルURLも確認する。URLを取得できなければ推測しない。

ほかの参加者のファイルは開かない。

## コネクタまたはAPIで提出する

本人がAI経路を希望した場合だけ使う。未接続の場合は、標準のブラウザ提出と、時間・環境が許す発展の接続体験を提示し、一問だけ選んでもらう。

未接続から始める場合：

1. 使用中のAIとOSを確認する。
2. Google公式OAuthまたは公式コネクタの現在の案内を開く。
3. 一度に一操作だけ示す。
4. 権限画面が出るたび、目的、アクセス範囲、影響を説明し、本人へ確認する。
5. 接続後に読み取り確認を行う。秘密値や生のアカウント情報を出力しない。
6. 同じ箇所で3回または約7分止まったら、ブラウザ提出へ戻る。

接続済み、または接続確認後：

1. 指定フォルダID `1sEgVfferbokBUQU440bChvVYyGk338hs`を対象として確認する。似た名前のフォルダを推測で選ばない。
2. 対象ファイル、対象フォルダ、影響を示し、本人の明確な承認を得る。
3. 新規ファイルを1件だけアップロードする。
4. 同じフォルダの一覧またはファイルメタデータを読み戻す。
5. 完全一致するファイル名とアップロード経路を確認し、取得できる場合だけ個別ファイルURLも確認する。

接続に時間がかかる、権限を判断できない、公式経路を確認できない場合は、ブラウザ経路へ切り替える。

## private Issueへ結果を残す

成果物を一覧またはメタデータで確認できた後だけ、参加者自身のprivate app repoにある進行中Issueへ記録する。表示名はセッション開始時に確認済みの値を使う。

`scripts/support-session.mjs`の`--help`に`artifact`が表示される場合だけ、次を使う。

```bash
node scripts/support-session.mjs artifact \
  --filename "2026-08-23_表示名_成果物.zip" \
  --folder-id "1sEgVfferbokBUQU440bChvVYyGk338hs" \
  --parent-verified \
  --drive-url "read-backで確認した個別ファイルURL" \
  --upload-route "browser" \
  --read-back-verified \
  --summary "受講者共有用フォルダへの成果物提出を確認" \
  --next "講師へ提出完了を伝える"
```

`--folder-id`は2026年8月23日の指定値に完全一致させる。`--parent-verified`は、ファイル名だけでなく、そのファイルの親が指定フォルダだとDriveから確認できた場合だけ付ける。`--upload-route`は実際の経路に合わせて`browser`、`connector`、`api`のいずれかを使う。`--drive-url`へ提出先フォルダURLを渡さない。個別ファイルURLを確認できなければURLを推測せず、この引数を省略する。

このコマンドは、ファイル名、成果物の個別Drive URLまたは未記録、経路、Drive read-back確認、要約、次の一手を同じprivate Issueへ記録し、GitHubからも読み戻す。Issueには生のフォルダIDを残さず、提出先を`街場のAI屋さん・当日成果物フォルダ`と記録し、親とファイル名を確認済みと残す。公開教材repoでは実行しない。

Driveでファイルと親を確認できた状態と、GitHub Issueで提出コメントをread-backできた状態は別々に報告する。

- Drive確認済み・Issue未反映：ファイルを再アップロードせず、`artifact`または`sync`によるIssue記録だけを再開する。
- Drive未確認・Issue未記録：提出済みとせず、まず指定フォルダ直下を一度だけ確認する。
- Drive確認済み・Issue確認済み：提出と記録の両方が完了。

## 失敗した場合

- アップロード完了表示だけで、一覧またはメタデータを確認できない：`提出済み`と言わない。
- 権限エラー：共有権限を変更せず、講師へ引き継ぐ。
- 同名ファイルがある：上書きせず、日時または短い連番を付けた新しい名前を本人へ確認する。
- コネクタ/APIが使えない：希望者の発展課題として一操作ずつ確認し、同じ箇所で3回または約7分止まったらブラウザ経路へ切り替える。
- ZIPに除外対象が見つかった：アップロードせず、安全なZIPを作り直す。
- GitHubへ結果を記録できない：Drive提出とGitHub記録を分け、提出確認済みでも記録状態は「未反映」とする。再開カードへ安全な要約だけを残す。
