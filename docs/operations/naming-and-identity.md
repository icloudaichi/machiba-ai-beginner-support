# 参加者の名前と保管場所を分ける

運営が把握したい氏名と、参加者が講座で使いたい名前は別に管理します。GitHubのrepo名やDriveのファイル名も、同じ値を自動で使い回しません。

| 種類 | 誰が決めるか | 例 | 保存場所 |
| --- | --- | --- | --- |
| 運営上の氏名 | 申込者・運営 | 申込時の氏名 | 閲覧制限した申込情報・運営台帳 |
| 講座のニックネーム | 参加者 | `だいち`、`ねこさん` | 最初はこの端末の進捗。別途了承後に本人のprivate Issue |
| GitHubのrepo名 | AIが提案し本人が確認 | `machiba-ai-app` | GitHub |
| Drive提出用の名前 | 参加者が提出時に確認 | 任意のニックネーム | 共有ZIPのファイル名 |

## 運営上の氏名

申込者の確認や個別フォローに必要な氏名は、閲覧者を限定した申込情報・運営台帳に置きます。公開教材repo、公開Issue、参加者の相談Issueへ氏名をコピーしません。

運営台帳では、必要最小限の範囲で「申込時の氏名」「本人が選んだニックネーム」「本人のprivate repo URL」を対応させられます。台帳そのものをこの公開リポジトリへ置かず、アクセスできる運営担当者を限定します。

## 講座のニックネーム

参加者には次のように案内します。

> 講座では何と呼ばれたいですか？ 本名でなく、好きなニックネームで大丈夫です。日本語でも構いません。まず、この端末の進捗にだけ保存します。

サイトの開始時は、用途を説明してこの端末の進捗にだけ保存します。private repoと記録ツールを確認した後、同じニックネームをIssueにも使うか、見える相手を説明して別に確認します。端末保存の了承をIssue保存へ流用しません。英字へ直す必要はありません。メールアドレス、GitHubユーザー名、電話番号などは使いません。

Issue開始後はサイト上のニックネーム欄を固定します。次回から別の名前を使いたい場合はAI相談室で確認し、既存Issueの自動改名や、名前変更だけを理由にしたIssueの自動作成は行いません。

## GitHubのrepo名

repo名は参加者名ではなく、作品を置く技術的な保管場所名です。AIが次の順で提案します。

1. `machiba-ai-app`
2. 同名があれば`machiba-ai-app-2`
3. さらに同名があれば末尾の数字を増やす

小文字のASCII英字、数字、ハイフンだけを使い、本名やニックネームを含めません。アプリ画面に表示する日本語タイトルとは別なので、参加者へ英字のニックネームを考えてもらう必要はありません。

## Drive提出用の名前

共有Driveではファイル名がほかの参加者やリンク所持者に見えます。private Issueのニックネームをそのまま流用せず、同じ名前を使うか、提出用に別の名前を使うかを提出時に確認します。

この確認は、private Issueへのニックネーム保存やDriveへのアップロード承認とは別です。

## 現時点で導入しないもの

参加者コードや参加者IDへの移行は、今回の運用変更には含めません。必要になった時点で、採番、既存データとの対応、運営台帳のアクセス権を別途設計します。

AIが使う具体的な判断規則は、[名前と保存先を分ける](../../.agents/skills/machiba-beginner-support/references/naming-and-identity.md)を正本とします。
