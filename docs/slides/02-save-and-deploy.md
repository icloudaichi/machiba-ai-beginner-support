# 02 つなぐ・セーブする・公開する

## 01｜つなぐ・セーブする・公開する

接続確認→一つ変更→保存→希望者は公開。できた節目を区別して残します。

## 02｜今日の到達点

接続だけで終わった人も、保存まで進んだ人も、最後に成功したところから再開します。

## 03｜3つの鍵

サービスへの登録、AIの接続、PCの認証は別。Googleログインだけで全部完了するわけではありません。

## 04｜公式サイトでアカウント登録

[GitHub](https://github.com/signup)、[Cloudflare](https://dash.cloudflare.com/sign-up)。Googleで続行が表示される場合はそれを利用。既存アカウントがある人は新しく作らずログインします。

## 05｜メール認証とログイン

表示に従い本人が認証します。パスワード、認証コードはAIへ貼りません。迷ったら秘密を隠して画面の説明を求めます。

## 06｜GitHubをAIにつなぐ

使用AIの連携追加画面で、GitHub用の機能と提供元を確認。本人のアカウントで認証し、必要なリポジトリだけを対象にします。読み取りだけの連携はコード保存には使えない場合があります。

## 07｜CloudflareをAIにつなぐ

Codexでは[公式案内](https://developers.cloudflare.com/agent-setup/codex/)に沿いPluginsからCloudflareを追加し、OAuth画面で権限を確認します。Claude Codeではその製品の対応方法を確認します。

## 08｜PCの認証も別に確認

Git/ghはGitHub操作の道具。WranglerはCloudflareの開発・公開用の道具です。コネクタの接続済み表示だけでは、それらの認証済みを証明できません。

## 09｜読み取りから始める

接続と対象の確認を先に。接続のための許可は公開や削除の許可とは別です。

## 10｜GitHubはセーブポイント

ファイルを変更→区切りをコミット→GitHubへプッシュ→GitHub上の反映を確認。

## 11｜セーブの依頼

```text
今回の変更を検証し、内容が分かる名前でコミットしてGitHubへ送ってください。
秘密情報や関係のない変更を含めないでください。
GitHub上に反映されたところまで確認し、変更内容と確認結果を記録してください。
まだ公開しないでください。自動公開設定がある場合は送信前に止めて説明してください。
```

## 12｜ロードは何をしたいか伝える

別PCへ取得するならクローン、今の作業を最新にするなら更新、前の版へ戻すなら復元です。変更を上書きする前に未保存の作業を保護します。

```text
このプロジェクトの現在の変更とGitHubの状態を確認してください。
前回の続きから再開したいです。未保存の作業を消さず、必要な操作を説明してください。
まだ復元や上書きは実行しないでください。
```

## 13｜Issueは冒険日誌

相談、試行、失敗、解決、学び、次の一手を要約して残します。本人の個人履歴は本人のprivate repoへ。公開教材には投稿しません。同梱サポート機能の準備と本人了承が必要です。

## 14｜Cloudflareは公開用サーバー

公開する作業はデプロイ。GitHubへ保存したこととは別です。

## 15｜公開前に確認

READMEと設定をAIに読んでもらい、対象アカウント・アプリ名・公開範囲・費用を確認してから公開します。

```text
このアプリをCloudflareへ公開する準備状況を確認してください。
対象、公開される情報、アクセス制御、費用、既存サイトへの影響を説明してください。
まだ公開せず、私の確認を待ってください。
```

## 16｜公開後に確かめる

URLを開く→ボタンを押す→データを追加→再読み込み→保存が残るか。URLが出ただけでは完成にしません。

## 17｜DBはAIとアプリの図書館

タスクや返信を整理して保存する場所。教材ではCloudflare D1を使用。情報を保存しただけでAIが自動学習するわけではありません。

## 18｜DBのつなぎ方

ブラウザ↔Workerの処理↔D1。DB作成→テーブル準備→`DB`というバインディングで接続→架空データの保存テスト。GitHubのコード復元はDBのデータ復元とは別です。

## 19｜自分専用とサービス化

private GitHubは公開サイトの鍵ではありません。ログイン・権限管理・バックアップ・費用確認を別途準備します。最初は架空データで確認し、本物の顧客情報を教材へ入れません。

## 20｜休憩と個別フォロー

最後にできたこと、今の画面、試したこと、次の一操作を講師に伝えます。
