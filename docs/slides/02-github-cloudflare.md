## 01 セーブして、必要な人に届けよう

接続を確かめ、変更を残し、必要な人だけ公開へ。
GitHub × Cloudflare × Codex

## 02 今日の道筋は、4つだけ

接続確認 → 変更 → 保存 → 希望者は公開

まず読めることを確認。次に小さく変更し、GitHubへ保存。公開は最後に、希望する人だけ進みます。

## 03 GitHubは、アプリづくりのセーブポイント

作ったファイルと変更の記録をインターネット上に保管する場所です。
「いつ、何を変えたか」を残せます。前の状態を調べたり、仲間と共有できます。

AIに「GitHubに保存して」と頼もう。
PCへの保存と、GitHubへの保存は別の操作です。

実画面：MDNの公開サンプル。https://github.com/mdn/beginner-html-site-styled

## 05 秘密の入力は、本人だけ

本人以外は入力しない。
パスワードと認証コードは、本人確認そのもの。画面共有中も読み上げず、自分の手で入力します。

## 06 このAIからGitHubを使えるか

登録 → 接続 → 確認

1. アカウントを持っている：サービスに自分の席がある
2. このAIから接続できる：使う道具でログインできている
3. 対象の情報を読める：指定した保管箱を一件確認する

## 07 保存には、3つの段階がある

- ファイル変更：手元で直す
- コミット：変更を説明付きで記録
- プッシュ：GitHubへ送る

## 08 AIへの頼み方は、順番を明確に

> 変更内容と動きを確認し、何を変えたか説明を付けて記録し、GitHubへ送ってください。Web公開はまだしないでください。

詳しくは資料06のセーブ用プロンプトへ。

動きを確認する → 変更の説明を残す → GitHubへ送る → Web公開はしない

## 09 前回の続きを、安全に始めよう

- 作業場所を開く：同じアプリのフォルダを選ぶ
- 記録を読む：Issueとファイルを確認
- 次の一つを決める：残りをAIと整理

資料06のロード用プロンプトで相談。今ある変更を残して、続きを確認します。

## 10 GitHubの言葉を、いつもの言葉に

| 用語 | いつもの言葉 |
| --- | --- |
| Repository｜リポジトリ | 作品の保管箱 |
| Commit｜コミット | セーブポイント |
| Issue｜イシュー | 相談・作業の日誌 |
| Clone｜クローン | 最初にPCへ複製する |
| Push｜プッシュ | PCの記録をGitHubへ送る |
| Pull｜プル | GitHubの変更をPCへ取り込む |

操作はAIに頼んで大丈夫。返事に出てきた言葉を、ここで確かめましょう。

## 11 Issueは、あとで効く“冒険日誌”

相談したこと／試したこと／失敗と解決／学びと次の一手

非公開の保管箱に記録します。
招待した人も読めます。見られる人を確認しましょう。

## 12 確認して、みんなの版へ

- 別に直す：ブランチ＝別の作業場所。原稿のコピーに直すイメージ
- 確認：PR＝変更を見せる相談。レビュー＝中身の確認
- 合流：マージ＝変更を合流。確認した修正を取り込む

一人で作るときは、自分で確認して保存。共同制作では、決めたルールで合流します。

## 13 Cloudflareは、Webアプリを公開する場所

アプリをネット上で動かし、URLから画面を開けるようにします。
この講座では、Workersを使います。画面の配信と、裏側の処理を担当します。

公開する作業を「デプロイ」と呼びます。
自分だけで使う場合は、入場制限も設定します。

## 15 保存と公開は、別の仕事

GitHub（保存）→ デプロイ（公開する作業）→ Cloudflare（公開サーバー）

保存と公開は別の操作です。自動デプロイを設定している場合は、GitHubへ送ると公開先も更新されます。保存前にAIと設定を確認しましょう。

## 16 公開前に、誰が使えるか確認

- 個人情報・秘密がない
- 練習には架空データ
- 誰が見られるか
- 誰が変更できるか
- 公開先と費用

AIに説明させる／設定をチェック
GitHubが非公開でも、Webは別に確認。
