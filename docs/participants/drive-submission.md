# 成果物をGoogle Driveへ提出する

2026年8月23日の講座で作った成果物は、次の共有フォルダへ提出します。

- [2026.8.23開催／受講者共有用](https://drive.google.com/drive/folders/1sEgVfferbokBUQU440bChvVYyGk338hs)

標準は、ブラウザから自分でアップロードする方法です。Google DriveコネクタやAPIは初回講座の必須設定ではありません。すでに使える場合、または時間に余裕があり「AIからDriveへ提出できるよう接続してみたい」場合だけ、発展として選べます。

## 提出前に知っておくこと

このフォルダは、リンクを知っている人が閲覧・追加できる共有場所です。ファイル名に入れる表示名は、ほかの参加者やリンク所持者にも見えます。本名でなく、ニックネームで構いません。

GitHubのprivate Issueへ表示名を保存する確認と、共有フォルダのファイル名に表示名を使う確認は別です。AIはアップロード前に、もう一度確認します。

自分の提出ファイルだけを追加してください。ほかの人のファイルを開く、移動する、名前を変える、削除する操作や、フォルダの共有権限を変える操作は行いません。

この直接URLと書き込み権限は公開教材から見えます。2026年8月23日18:00の講座終了後、運営は新規追加を止めるため共有権限を見直します。

## ファイル名

```text
YYYY-MM-DD_表示名_成果物.zip
```

例：`2026-08-23_だいち_成果物.zip`

ZIPには次を入れません。

- `.env`、秘密鍵、トークン、パスワード、認証コード
- `node_modules`、`.wrangler`、`.git`のローカル状態
- 本物のお客様や参加者の情報
- 個人用の会話全文やスクリーンショット

## AI相談室へ貼る文章

対象プロジェクトを開いたCodexまたはClaude CodeのAI相談室で使います。

```text
このプロジェクトの成果物を、2026年8月23日の受講者共有用Google Driveフォルダへ提出する準備をしたいです。

提出先：
https://drive.google.com/drive/folders/1sEgVfferbokBUQU440bChvVYyGk338hs

まず、この共有フォルダではファイル名がほかの参加者やリンク所持者にも見えることを説明し、ファイル名に使う表示名を一問だけ確認してください。GitHubのprivate Issueへ保存した表示名をそのまま使う場合も、共有ファイル名へ使ってよいか別に確認してください。

次に、YYYY-MM-DD_表示名_成果物.zipを作る準備をしてください。.env、秘密鍵、トークン、認証コード、node_modules、.wrangler、.git、個人・顧客データを除外し、ZIPの内容を確認してください。

アップロードは標準ではブラウザから手動で行います。Google DriveコネクタまたはAPIがすでに利用可能なら、私へ経路を選ぶ質問をしてください。未接続で私が「AIから提出できるよう接続してみたい」と希望した場合だけ、使用中のAIとOSを確認し、Google公式OAuthまたは公式コネクタを一操作ずつ案内してください。

接続の権限画面では、目的、見える情報、影響を毎回説明し、私の確認を待ってください。APIキー、認証コード、トークンをチャットへ貼らせないでください。接続の確認とアップロードの確認は別です。同じ箇所で3回または約7分止まったら、ブラウザ提出へ戻してください。画面名は変わることがあるため、表示を確認せず固定のボタン名を断定しないでください。

書き込み直前に、対象ファイル、対象フォルダ、リンク所持者に見える影響を説明し、「この内容でアップロードしてよいですか？」と一問だけ確認してください。私が了承する前にアップロードしないでください。

共有権限を変更せず、自分のファイルを新規追加するだけにしてください。既存ファイルを開く、更新する、移動する、改名する、削除する操作はしないでください。

アップロード後は、同じファイル名が一覧にあることと、そのファイルの親が提出先フォルダID 1sEgVfferbokBUQU440bChvVYyGk338hs であることを読み戻してください。親とファイル名を確認できない場合は提出済みと言わないでください。個別URLは確認できた場合だけ記録し、確認できなければ省略して、URLを推測しないでください。

確認できたら、scripts/support-session.mjsの--helpにartifactがある場合だけ、--folder-id 1sEgVfferbokBUQU440bChvVYyGk338hs と --parent-verified を指定し、表示名、ファイル名、実際の経路、確認結果、次の一手を、この参加者private repoの進行中Issueへ記録してGitHubから読み戻してください。Issueには生のフォルダIDを残さず「街場のAI屋さん・当日成果物フォルダ」と親確認済み状態を記録してください。個別Drive URLは確認できた場合だけ加えてください。公開教材repoへ個人の提出記録を書かないでください。

Driveで親とファイル名を確認できた状態と、GitHub Issueで提出記録を確認できた状態を別々に報告してください。Drive確認済み・Issue未反映なら再アップロードせず、Issue記録だけを再開してください。

一度に一問または一操作だけ進めてください。
```

## 制作タスクへ貼る文章

ZIP作成と提出作業を別の制作タスクで行う場合に使います。同じrepoの進行中Issueを再利用し、新しいIssueを重複作成しません。

```text
このプロジェクトの提出用ZIPを作り、確認後にGoogle Driveへ提出したいです。

提出先：
https://drive.google.com/drive/folders/1sEgVfferbokBUQU440bChvVYyGk338hs

最初にsupport-sessionのstatusを確認し、このrepoで進行中の同じ相談Issueを使ってください。別cloneで状態がなければ、私が示すIssue番号だけでresumeしてください。似たIssueを推測しないでください。

ファイル名はYYYY-MM-DD_表示名_成果物.zipです。共有フォルダ内で表示名が見えることを説明し、表示名をファイル名へ使う了承を別に確認してください。

.env、秘密鍵、トークン、認証コード、node_modules、.wrangler、.git、個人・顧客データを除外してください。ZIP作成後に内容一覧を確認し、除外できたことを短く教えてください。生のファイル一覧やローカル絶対パスはGitHub Issueへ保存しないでください。

標準はブラウザでの手動アップロードです。コネクタ/APIが使える場合、または私が発展として接続を希望した場合だけ、指定フォルダIDへの新規アップロードを案内してください。未接続なら使用中のAIとOSを確認し、Google公式OAuthまたは公式コネクタを一操作ずつ案内し、権限画面ごとに目的と影響を説明して確認を待ってください。APIキー、認証コード、トークンは貼らせないでください。同じ箇所で3回または約7分止まったら、ブラウザ提出へ戻してください。既存ファイルの操作と共有権限変更は禁止です。

アップロード直前に、対象ファイル、対象フォルダ、影響を示し、私の明確な了承を待ってください。完了後は一覧またはメタデータを読み戻し、完全一致するファイル名と、親がフォルダID 1sEgVfferbokBUQU440bChvVYyGk338hs であることを確認してください。個別ファイルURLは確認できた場合だけ記録してください。

scripts/support-session.mjsの--helpにartifactが表示される場合だけ、--folder-id 1sEgVfferbokBUQU440bChvVYyGk338hs --parent-verified を付けて確認済みの提出結果をprivate Issueへ記録し、GitHubでもread-backしてください。Issueには生のフォルダIDを残さないでください。個別URLを確認できない場合は作らず、その引数を省略してください。Drive確認済みとIssue確認済みを分けて報告してください。
```

## 途中で止まったら

- 「アップロード完了」と表示されても、フォルダ一覧で確認できなければ提出済みではありません。
- 権限エラーが出ても、共有設定は変更しません。講師へ確認します。
- 同じ名前のファイルがあっても、上書きしません。
- AI接続や提出で同じ箇所に3回、または約7分止まったら、ブラウザからの手動アップロードへ戻ります。
- GitHubへの記録だけ失敗した場合、Drive提出の成否と記録の成否を分けて伝えます。

再開するときは、[再開カード](../../.agents/skills/machiba-beginner-support/references/resume-card.md)の「Google Drive提出」欄を使います。
